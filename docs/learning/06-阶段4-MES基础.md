# 06 - 阶段 4：MES 基础（BOM + 工单 + 领料 + 完工入库）

## 一、本阶段目标

让进销存系统升级为**真正的"产-供-销"闭环**：在进销存的库存核心之上，叠加 MES（制造执行）能力。

完成本阶段后，业务流可以闭环：

```
采购入库(原料) → 创建 BOM → 创建工单 → 下达工单 → 领料(扣原料库存)
                                                        ↓
销售出库(成品) ← 完工入库(增成品库存,自动算成本) ← (生产)
```

---

## 二、关键设计决策（经用户确认）

| # | 决策 | 选择 | 原因 |
|---|------|------|------|
| 1 | BOM 层级 | **单级 BOM** | 中小厂 95% 够用，多级要做需求倒推，复杂度+50% |
| 2 | 领料模式 | **按需领料** | 下达后随时领，可多次领，符合实际车间 |
| 3 | 成本核算 | **实际成本法** | 完工成本 = 累计领料金额 ÷ 完工总数量 |
| 4 | 数量校验 | **严格不允许超领/超完工** | MES 的根本价值是约束 |
| 5 | 单号前缀 | **SCGD/LL/RK** | 与现有 CGRK/XSCK 中文拼音风格一致 |

## 三、数据模型（7 张新表）

```
mfg_bom                BOM 头（成品 + 版本 + 状态）
mfg_bom_item           BOM 行（子物料 + 单位用量 + 损耗率）

mfg_work_order         工单头（成品 + BOM + 计划数 + 状态机）
mfg_work_order_item    工单物料需求（下达时按 BOM × 计划数展开的快照）

mfg_issue              领料单头（关联工单 + 仓库）
mfg_issue_item         领料单行（物料 + 货位 + 数量，UnitCost 由引擎填）

mfg_receipt            完工入库单（单成品 + 数量 + 自动算成本）
```

**没有 `mfg_receipt_item` 表**——一张完工单只入库工单上的成品（单成品工单），数量是头字段。

### BOM 快照模式

**问题**：BOM 改了，正在跑的工单怎么办？
**方案**：工单 `Release` 时复制 BOM 行到 `mfg_work_order_item`，后续 BOM 修改不影响该工单。

工单上保留 `BomID` 是为了追溯用了哪个版本，但数量需求只看自身的 `Items`。

## 四、状态机

### 工单状态（6 态）

```
草稿(1) ──编辑/删除──┐
   │下达
   ▼
已下达(2) ──首次领料触发──┐
   │作废(无领料无完工)     │
   ▼                       │
生产中(3) ◀────────────────┘
   │完工累计达到计划数
   ▼
已完工(4) ──关闭──→ 已关闭(5)
   │作废(必须先冲销所有领料和完工)
   ▼
已作废(9)
```

### 领料/完工单状态（3 态，沿用进销存）

```
草稿(1) ──确认──→ 已执行(3) ──作废──→ 作废(4)
   │删除
   ▼
（不存在）
```

## 五、核心实现要点

### 5.1 复用 inventory 模块，不重写

> "MES 不重写库存逻辑，所有库存动作都调用进销存的 `StockEngine.Apply()`。"

具体做法：
- 在 `inv_stock.go` 新增 `BizMfgIssue` / `BizMfgReceipt` 常量
- 在 `sequence.go` 给两种业务新增前缀 `LL` / `RK`，工单单独加 `MFG_WORK_ORDER → SCGD`
- 在 MES service 中 `import invsvc` 直接调 `stockEngine.Apply()`

效果：MES 的领料、完工、作废冲销，每一笔都自动写入 `inv_stock_flow`，与采购销售流水统一在一张表查询。

### 5.2 下达工单：BOM 展开

```go
for _, bi := range bom.Items {
    req := bi.Quantity * d.PlanQty * (1 + bi.LossRate)
    tx.Create(&MfgWorkOrderItem{
        WorkOrderID: id,
        ProductID:   bi.ProductID,
        RequiredQty: req,
    })
}
```

**为什么不在 Confirm 领料时实时算 BOM？** 因为 BOM 可能被改、被停用——快照保证工单可追溯。

### 5.3 领料超领校验

```go
if woItem.IssuedQty + it.Quantity > woItem.RequiredQty + 0.0001 {
    return fmt.Errorf("物料 %d 超领：需求%.4f 已领%.4f 本次%.4f",
        it.ProductID, woItem.RequiredQty, woItem.IssuedQty, it.Quantity)
}
```

注意 `+0.0001` 是**浮点容差**——decimal(18,4) 精度下避免 `0.9999999 < 1.0` 这种边界拒绝。

### 5.4 领料：让 StockEngine 自动取出库均价

```go
stockEngine.Apply(tx, StockMoveParam{
    BizType:   BizMfgIssue,
    Direction: DirOut,
    Quantity:  it.Quantity,
    // 不传 UnitCost → 引擎按 stock.AvgCost 出库
})
// 出库后从流水反查实际单价回写到 mfg_issue_item
var lastFlow InvStockFlow
tx.Where("biz_no=? AND biz_item_id=?", d.DocNo, it.ID).Order("id DESC").First(&lastFlow)
it.UnitCost = lastFlow.UnitCost
it.Amount   = lastFlow.TotalAmount
```

**为什么反查**？前端不知道当前均价是多少，所以创建时填 0；执行时让引擎用真实成本，再回写到单据。

### 5.5 完工入库：自动算单位成本

```go
unitCost := wo.IssuedAmount / (wo.ActualQty + d.Quantity)
stockEngine.Apply(tx, StockMoveParam{
    BizType:   BizMfgReceipt,
    Direction: DirIn,
    Quantity:  d.Quantity,
    UnitCost:  unitCost, // ★ 显式传入计算后的成本
})
```

举例：
1. 工单计划做 100 个 A，BOM 是 B×2 + C×3
2. 领料：B 200个@10 = 2000，C 300个@5 = 1500，累计 `IssuedAmount = 3500`
3. 完工入库 50 个：unitCost = 3500 / (0+50) = 70
4. 再完工入库 50 个：unitCost = 3500 / (50+50) = 35 ← 因为累计领料金额已经在第一次分摊掉了一半

**注意：这是简化模型**。严格的实际成本法应该让总金额 = 3500，但简单实现会把 3500 重复分摊。
正确做法见**踩坑记录 8.2**。

### 5.6 作废冲销

所有 Confirm 都对应一个 Void，原则：**反向调用 StockEngine 抵消，并回退工单累计字段**。

```go
// 领料作废
stockEngine.Apply(tx, StockMoveParam{
    Direction: DirIn,          // 反向！原是出库，作废就入库
    UnitCost:  it.UnitCost,    // 按当时出库的成本回库，不污染均价
    Remark:    "作废冲销",
})
woItem.IssuedQty -= it.Quantity  // 工单需求回退
```

## 七、Go 学习要点

### 7.1 跨模块复用：`import invsvc "service/inventory"`

MES 服务直接复用 inventory 的库存引擎：

```go
import (
    invsvc "service/inventory"
)

var (
    stockEngine = &invsvc.StockEngine{}
    seqService  = &invsvc.SequenceService{}
)
```

**重命名 import**（`invsvc`）的好处：消除包名冲突（inventory 包名 + manufacturing model 引用的 inventory model），同时让 service 调用看起来更明确。

### 7.2 错误处理的"防御链"

`IssueService.Confirm` 的校验链：

```go
if d.Status != Draft { return errors.New(...) }
if wo.Status not in [Released, InProgress] { return errors.New(...) }
if it.Quantity <= 0 { return errors.New(...) }
if woItem == nil { return fmt.Errorf("物料 %d 不在工单需求中") }
if woItem.IssuedQty + it.Quantity > RequiredQty { return fmt.Errorf("超领") }
```

**每一步都返回 error 让事务回滚**。Go 没有异常，靠这种"早返回"模式表达"出错就拒绝"。

### 7.3 map 作为索引避免 O(N²)

```go
woItemByPid := make(map[uint]*MfgWorkOrderItem)
for i := range wo.Items {
    woItemByPid[wo.Items[i].ProductID] = &wo.Items[i]
}
// 后面 O(1) 查找
woItem := woItemByPid[it.ProductID]
```

**注意 `&wo.Items[i]` 而不是 `&item`**：循环变量 item 在每次迭代是同一个内存地址，取址会全指向最后一个。`&slice[i]` 才是稳定的元素地址。

### 7.4 浮点容差

```go
if newActual >= wo.PlanQty - 0.0001 {
    updates["status"] = WoStatusFinished
}
```

`decimal(18,4)` 精度下，避免 `99.9999 < 100.0` 这种边界判定。

## 八、踩坑与注意事项

### 8.1 GORM 关联预加载层级

`Preload("Items.Product")` 加载子项与子项的关联商品，**两层**。
如果还要 `Items.Product.Category`，写 `Preload("Items.Product.Category")`。

### 8.2 实际成本法的简化版 vs 严格版

**当前实现（简化版）**：
```
unitCost = wo.IssuedAmount / (wo.ActualQty + 本次完工)
```
缺陷：每次完工独立用这个公式算，第二次完工时 IssuedAmount 没扣，会算偏。

**严格版**：维护 `wo.UnallocatedAmount`（未分摊领料金额）：
- 领料时 += 领料金额
- 完工时分摊一部分到本次完工成本，剩余继续等下次完工
- 全部完工后 UnallocatedAmount 应趋近 0（除非有损耗/超领）

**结论**：阶段 4 接受简化版，使用条件是"先全部领完再完工入库"（小批量生产场景成立）。阶段 5 加严格成本核算。

### 8.3 工单删除限制

工单一旦下达就不能"删除"，只能"作废"。
- 删除：物理删除记录，仅草稿
- 作废：保留记录、状态变 9、流水反向冲销

UI 上对应不同按钮，service 层强制校验。

### 8.4 同名包冲突

`model/manufacturing` 与 `service/manufacturing` 都叫 `manufacturing`，引用时容易混淆。
解决方案：service 文件里 `import "model/manufacturing"` 不重命名，service 自己叫 `manufacturing` 包，**通过结构体类型 `manufacturing.MfgBom` 引用 model**。GoLang 允许，编译时按 import 路径区分。

## 十、验证测试用例（建议联调清单）

### P0 - 基本流程
- [ ] 建 BOM：A=B×2+C×3（其中 B/C 已有商品资料）
- [ ] 入原料：B 100个@10、C 100个@5（采购入库）
- [ ] 建工单：做 A 30 个
- [ ] 下达工单：检查物料需求是否展开为 B=60、C=90
- [ ] 领料：B 60 个、C 90 个（出库扣原料库存）
- [ ] 完工入库：A 30 个 → 检查单位成本 = (60*10+90*5)/30 = 35
- [ ] 库存流水：可以看到 MFG_ISSUE × 2 条和 MFG_RECEIPT × 1 条

### P1 - 状态机
- [ ] 工单下达后不能删除
- [ ] 已领料的工单不能作废
- [ ] BOM 被工单引用后不能删除
- [ ] BOM 启用/停用切换

### P2 - 边界
- [ ] 超领料（一次性领 > 需求量）→ 拒绝
- [ ] 超完工（累计完工 > 计划数）→ 拒绝
- [ ] 损耗率：BOM B 设 5% 损耗，需求量应为 60 * 1.05 = 63
- [ ] 作废领料 → 原料库存回升、工单 IssuedQty 减少
- [ ] 作废完工 → 成品库存减少、工单 ActualQty 减少
