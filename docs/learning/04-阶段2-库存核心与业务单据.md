## 1. 阶段 2 设计纲要

### 1.1 业务单据矩阵（6 类）

| 单据 | BizType | 单号前缀 | 库存方向 |
|---|---|---|---|
| 采购入库 PurchaseOrder | `PURCHASE_IN` | `CGRK` | + 入 |
| 采购退货 PurchaseReturn | `PURCHASE_RETURN` | `CGTH` | − 出 |
| 销售出库 SalesOrder | `SALES_OUT` | `XSCK` | − 出 |
| 销售退货 SalesReturn | `SALES_RETURN` | `XSTH` | + 入 |
| 调拨 Transfer | `TRANSFER_OUT` + `TRANSFER_IN`（成对） | `DBDD` | 源仓出、目标仓入 |
| 盘点 Stocktake | `STOCKTAKE_ADJUST` | `PDDD` | 差额入/出 |

### 1.2 单据状态机（极简 3 态）

```
草稿(1) ──Confirm──▶ 已执行(3)        ──Void(仅草稿可作废)──▶ 作废(4)
                       │
                       └─ 已执行不可逆，需冲销请录反向单
```

只有 `Confirm` 这一个动作真正动库存；`Void` 仅对草稿合法。  
中间不设"已审核 (2)"——简化版 B 一步到位，未来扩展再插入。

### 1.3 库存真相 = 流水 + 余额

- **inv_stock_flow**：append-only 流水账，每行记录 `BeforeQty/AfterQty/BeforeAvg/AfterAvg`，是唯一真相。
- **inv_stock**：按 (ProductID, WarehouseID, LocationID) 唯一聚合，是 flow 的"最新快照"，便于查询。
- 任何库存变动都必须走 `StockEngine.Apply()`，**禁止**直接 UPDATE inv_stock。

### 1.4 移动加权平均成本

```
入库：new_avg = (old_qty*old_avg + in_qty*in_cost) / (old_qty + in_qty)
      （old_qty <= 0 时直接取 in_cost，避免负库存污染）
出库：avg 不变；出库成本 = 出库数量 * 当前 avg
调拨：源仓按当前 avg 出，目标仓按"源仓 avg"作为入库成本
盘点盈：按现有 avg 入；盘点亏：按现有 avg 出
```

## 3. 关键代码精读（Go 学习重点）

### 3.1 单号生成器：行锁 + 事务

`service/inventory/sequence.go`：

```go
return global.GVA_DB.Transaction(func(tx *gorm.DB) error {
    var seq inventory.InvDocSequence
    err := tx.Clauses(clause.Locking{Strength: "UPDATE"}).
        Where("biz_type = ? AND date_key = ?", bizType, dateKey).
        First(&seq).Error
    // ... 不存在则 Create；存在则自增 seq.Seq++
})
```

**Go 知识点**：
- `gorm.io/gorm/clause` 的 `Locking{Strength: "UPDATE"}` 翻译成 `SELECT ... FOR UPDATE`，并发安全。
- `Transaction(func(tx *gorm.DB) error { ... })`：闭包返回 nil 即提交，返回 err 即回滚——比手动 `Begin/Commit/Rollback` 安全得多。
- `errors.Is(err, gorm.ErrRecordNotFound)` 判 "不存在则创建"。

### 3.2 库存引擎：单一入口

`service/inventory/stock_engine.go` 的 `Apply` 方法：

```go
func (s *StockEngine) Apply(tx *gorm.DB, m StockMove) error {
    // 1) 行锁查/建当前库存 row
    // 2) 计算 newQty / newAvg
    // 3) 写 inv_stock_flow（append）
    // 4) UPDATE inv_stock（upsert）
}
```

设计要义：**所有动库存的代码必须调 Apply**。这样：
- 流水永远完整 → 任何时刻可重建余额；
- 加权平均算法只此一处 → 不会被某个新单据写错；
- 测试只需测 Apply。

### 3.3 单据 service 模板（以采购入库为例）

```go
func (s *PurchaseOrderService) Confirm(id uint, userID uint) error {
    return global.GVA_DB.Transaction(func(tx *gorm.DB) error {
        var doc inventory.InvPurchaseOrder
        if err := tx.Preload("Items").First(&doc, id).Error; err != nil { return err }
        if doc.Status != inventory.DocStatusDraft { return errors.New("仅草稿可执行") }
        for _, it := range doc.Items {
            if err := stockEngine.Apply(tx, StockMove{
                ProductID: it.ProductID, WarehouseID: doc.WarehouseID,
                LocationID: it.LocationID, QtyDelta: it.Qty, InCost: it.Price,
                BizType: inventory.BizPurchaseIn, BizDocID: doc.ID, BizDocNo: doc.DocNo,
            }); err != nil { return err }
        }
        return tx.Model(&doc).Updates(map[string]any{
            "status": inventory.DocStatusDone, "confirm_by": userID,
        }).Error
    })
}
```

**模板套路**：`事务 → 加载并校验 → for 明细调 Apply → 改状态`。6 个单据 90% 长这样，差异只在 `QtyDelta` 正负、`InCost` 来源。

### 3.4 router 用闭包减少重复

`router/inventory/documents.go`：

```go
bind := func(prefix string, x interface {
    Create(*gin.Context); Update(*gin.Context); Delete(*gin.Context)
    Confirm(*gin.Context); Void(*gin.Context)
    FindOne(*gin.Context); GetList(*gin.Context)
}) {
    g := r.Group(prefix)
    g.POST("", x.Create); g.PUT("", x.Update); g.DELETE("", x.Delete)
    g.POST("confirm", x.Confirm); g.POST("void", x.Void)
    g.GET("", x.FindOne); g.GET("list", x.GetList)
}
bind("purchaseOrder", &purchaseApi)
bind("salesOrder", &salesApi)
// ...
```

**Go 知识点**：
- 匿名 interface（structural typing）——只要类型有这 7 个方法就能传进来，无需显式 `implements`。
- 闭包捕获 `r *gin.RouterGroup`，避免 6 份重复路由块。
- 这是 Go 接口"鸭子类型"的经典用法。

## 7. 关键决策回顾（与设计对齐）

1. ✅ 状态机 3 态而非 5 态——简单、易验收，未来插入 "已审核" 不破坏。
2. ✅ 流水 + 快照双写——查询走 inv_stock 快，审计走 inv_stock_flow 准。
3. ✅ 调拨用 `TRANSFER_OUT` + `TRANSFER_IN` 两条流水而非一条——便于按仓库统计出入库。
4. ✅ 盘点结果 = 调整流水（无 PDDR 单独类型）——盘亏盘盈复用普通入出库语义。
5. ✅ 出库成本只读不改 avg——经典移动加权平均的标准实现。

## 9. 给学 Go 的你 — 本阶段 5 个重要语法/范式

1. **`Transaction(func(tx *gorm.DB) error)`**：用闭包返回值控制提交/回滚，是 Go 处理事务的"惯用法"。
2. **`clause.Locking{Strength:"UPDATE"}`**：行锁防并发；GORM 把数据库特性抽象成 clause 对象。
3. **匿名 interface 参数**：`func bind(p string, x interface{ M1(...); M2(...) })` 体现 Go 鸭子类型——结构兼容即满足。
4. **`errors.Is` / `errors.As`**：判别 sentinel error（如 `gorm.ErrRecordNotFound`）的正确姿势，比 `==` 更安全（支持 wrap）。
5. **包级变量做模块单例**：`var stockEngine = &StockEngine{}` —— Go 没有 DI 容器，包级变量+小写名做"内部单例"是常见手法；外部仍通过 ServiceGroup 暴露大写字段。
