## 三、核心设计：减少重复

### 3.1 痛点

最初我写了 `purchaseOrder/index.vue`（约 250 行）作为标杆页，准备复刻 5 份。问题：

- 6 份相似文件 = 1500 行 → 改一处 bug 要改 6 次
- 字段错配（`docDate` vs `bizDate`）只发现一次得改 6 处

### 3.2 解决方案：三层抽象

```
┌─────────────────────────────────────────┐
│  purchaseOrder/index.vue   (11 行薄壳)   │  ← 业务页
│  salesOrder/index.vue      (11 行薄壳)   │
│  ...                                     │
└─────────────────┬───────────────────────┘
                  │ <DocPage :api :partyKey ... />
                  ▼
┌─────────────────────────────────────────┐
│  _DocPage.vue   (~140 行)                │  ← 通用模板组件
│  - 列表 + 搜索 + Dialog + 明细行         │
│  - props 控制差异：title/api/partyKey   │
└─────────────────┬───────────────────────┘
                  │ ctx = useDocPage(api, options)
                  ▼
┌─────────────────────────────────────────┐
│  _useDocPage.js  (~120 行)               │  ← Composable 逻辑
│  - reactive state                        │
│  - getList / openDialog / onSubmit / ... │
└─────────────────────────────────────────┘
```

### 3.3 Composable 范式（Vue 3 关键概念）

`_useDocPage.js` 是一个**普通 JS 函数**，返回响应式状态 + 方法：

```js
export function useDocPage(api, options = {}) {
  const tableData = ref([])
  const formData = reactive({ ... })
  const getList = async () => { ... }
  const openDialog = async (type, row) => { ... }
  return { tableData, formData, getList, openDialog, ... }
}
```

这就是 Vue 3 取代 Vue 2 mixin 的方式——**显式导入、无命名冲突、TypeScript 友好**。

### 3.4 通用组件 + props 注入差异

`_DocPage.vue` 接受 props 来表达不同单据的差异：

```vue
<!-- purchaseOrder/index.vue -->
<DocPage
  title="采购入库单"
  :api="purchaseOrderApi"
  partyKey="supplierId"
  partyLabel="供应商"
  partyRel="supplier"
  :partyApi="getSupplierAll"
  confirmLabel="确认入库"
  defaultPriceField="purchasePrice"
/>
```

```vue
<!-- salesOrder/index.vue（仅 5 个 prop 不同）-->
<DocPage
  title="销售出库单"
  :api="salesOrderApi"
  partyKey="customerId"
  partyLabel="客户"
  partyRel="customer"
  :partyApi="getInvCustomerAll"
  confirmLabel="确认出库"
  defaultPriceField="salePrice"
/>
```

效果：4 个采购/销售页加起来只有 **44 行代码**（11×4），比一份完整页面还少。

## 四、API 工厂函数（JS 高阶函数）

后端 6 个单据共享 7 端点（create/update/delete/confirm/void/findOne/getList），如果手写就是 42 个 export。改用工厂：

```js
// documents.js
const makeDocApi = (base) => ({
  create:  (data)   => service({ url: base, method: 'post',   data }),
  update:  (data)   => service({ url: base, method: 'put',    data }),
  remove:  (data)   => service({ url: base, method: 'delete', data }),
  confirm: (data)   => service({ url: base + '/confirm', method: 'post', data }),
  void:    (data)   => service({ url: base + '/void',    method: 'post', data }),
  findOne: (params) => service({ url: base, method: 'get', params }),
  getList: (params) => service({ url: base + '/list', method: 'get', params })
})

export const purchaseOrderApi  = makeDocApi('/inv/purchaseOrder')
export const purchaseReturnApi = makeDocApi('/inv/purchaseReturn')
export const salesOrderApi     = makeDocApi('/inv/salesOrder')
export const salesReturnApi    = makeDocApi('/inv/salesReturn')
export const transferApi       = makeDocApi('/inv/transfer')
export const stocktakeApi      = makeDocApi('/inv/stocktake')
```

**学习要点**：JS 高阶函数（函数返回函数/对象）是减少样板代码的标准武器。Go 中等价物是返回 `func(...)` 的函数或返回结构体的工厂。

## 五、单据状态机的 UI 表达

后端三态：`1 草稿 / 3 已执行 / 4 作废`。前端按状态显示不同操作按钮：

| 状态 | 可操作按钮 |
|------|-----------|
| 草稿 (1) | 查看 / 编辑 / 确认 / 删除 |
| 已执行 (3) | 查看 / 作废 |
| 作废 (4) | 查看 |

实现方式：

```vue
<el-button v-if="row.status === 1" type="success" link @click="onConfirm(row)">确认</el-button>
<el-button v-if="row.status === 1" type="danger"  link @click="onDelete(row)">删除</el-button>
<el-button v-if="row.status === 3" type="warning" link @click="onVoid(row)">作废</el-button>
```

## 六、明细行编辑（el-table 内嵌 input）

进销存的核心交互：一个单据 N 行明细，每行都要选商品、填数量、算金额。

关键技巧：

1. **el-table 的 data 直接绑响应式数组**（`formData.items`），增删行只需 push/splice
2. **金额自动计算**：`@change="calcRow(row)"` 在数量/单价变更时执行 `row.amount = qty * price`
3. **联动**：选商品时自动带出默认价（采购→purchasePrice，销售→salePrice）
4. **总计用 computed**：`totalAmount = computed(() => items.reduce(...))`

```vue
<el-table :data="formData.items">
  <el-table-column label="数量">
    <template #default="{ row }">
      <el-input-number v-model="row.quantity" @change="calcRow(row)" />
    </template>
  </el-table-column>
</el-table>
```

## 七、特殊页面

### 7.1 仓间调拨（transfer）

调拨与其他单据的差异：

- **双仓库**：`fromWarehouse` / `toWarehouse`
- **双货位**：`fromLocationId` / `toLocationId`
- **校验**：源仓与目标仓不能相同
- **无金额字段**：库存按源仓均价结转

由于差异较大，没有套用 `_DocPage.vue`，而是独立实现（~150 行）。

### 7.2 盘点（stocktake）

特点：

- 账面数 `bookQty` **只读**——后端在确认时根据系统库存快照填入
- 实盘数 `actualQty` 由用户输入
- 差异 `diffQty = actualQty - bookQty`，前端实时计算并染色（绿盈/红亏）

```vue
<el-input-number v-model="row.actualQty"
  @change="row.diffQty = Number(((row.actualQty||0)-(row.bookQty||0)).toFixed(4))" />
```

### 7.3 库存查询（stockBalance / stockFlow）

只读列表页，无 Dialog。流水页展示了关键字段：`bizType`（业务类型）、`direction`（出/入）、`qtyBefore`、`qtyAfter`，便于审计追溯每一次库存变更。

## 八、踩坑记录

### 8.1 字段名错配（最严重）

最初凭直觉用 `docDate` / `qty` / `price`，后来核对后端 `inv_documents.go`，发现实际字段是：

| 错误 | 正确（后端 model 权威） |
|------|------------------------|
| `docDate` | `bizDate` |
| `qty` | `quantity` |
| `price` | `unitPrice` |
| `totalQty` | （后端没有，前端 computed） |

教训：**写前端前一定要先 grep 一遍后端 struct 字段**。

### 8.2 PowerShell 不是 bash

Windows + PowerShell 环境下：
- `mkdir a b c` 失败（无法多参数）
- `&` 需要转义
- `dir /b` 需要 `cmd /c "dir /b"`
- 复杂正则替换用 PowerShell 经常翻车——直接删除文件重写更稳

### 8.3 write 工具不能覆盖

VentureMES 工作流中 `write` 拒绝覆盖已存在文件。被迫先 `del` 再 `write`，或改用 `edit`。

## 十、Vue 3 与 Go 的概念对照

| Vue 3 | Go | 说明 |
|-------|-----|------|
| `ref(x)` / `reactive(obj)` | `*T` 指针 + 通知 | 响应式数据 |
| `computed(() => ...)` | （无直接对应） | 派生值 + 缓存 |
| Composable 函数 | service 层方法集合 | 组合式逻辑复用 |
| `defineProps` | 函数参数 | 组件入参 |
| `script setup` | （无对应） | 编译期魔法，自动暴露顶层变量到模板 |
| `el-table.data` | `[]struct` + JSON tag | 数据源 |

学到的核心理念：**Vue 3 的 Composition API 让组件像写 Go service 一样自由组合，告别 Vue 2 的 OOP 死结构**。
